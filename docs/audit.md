# BISESJ Website Prototype Audit (Sprint 1 - S1-01)

## 1. Folder Layout and app/ vs src/ Coexistence

### Current Directory Structure
```
bisesj-homepage-development/
├── app/
│   ├── globals.css          # Tailwind CSS v4 directives and color variables
│   ├── layout.tsx           # Root layout with metadata, JSON-LD, fonts, analytics
│   └── page.tsx             # Homepage single-page assembly
├── components/
│   ├── site/                # Feature components (admissions, campus, enquiry, footer, header, hero, etc.)
│   └── ui/                  # Shadcn UI primitives (button, input, label, tabs, textarea)
├── lib/
│   └── utils.ts             # Tailwind class merging utility (clsx + twMerge)
├── public/                  # Static placeholder assets and icons
├── src/
│   ├── assets.ts            # Image URLs hotlinked to bisesjsa.com/wp-content/uploads
│   ├── content.ts           # Site content, copy, translations (EN/AR/BN), stats definitions
│   └── links.ts             # External and internal link targets, contact details
├── components.json          # Shadcn configuration
├── next.config.mjs          # Next.js configuration (remote image patterns for bisesjsa.com)
├── package.json             # Project metadata, scripts, dependencies
├── pnpm-lock.yaml           # Pnpm dependency lockfile
├── pnpm-workspace.yaml      # Pnpm workspace configuration
├── postcss.config.mjs       # PostCSS config with @tailwindcss/postcss
└── tsconfig.json            # TypeScript compiler configuration
```

### Why Both `app/` and `src/` Exist
The project was initially created as a single-page prototype generated by v0.
- v0 placed the Next.js App Router root layout and page directly inside `/app` at the repository root.
- Simultaneously, helper data files (`assets.ts`, `content.ts`, `links.ts`) were scaffolded into a top-level `/src` directory.
- In Next.js convention, projects typically follow either the root pattern (`/app`, `/components`, `/lib`) or the `src` directory pattern (`/src/app`, `/src/components`, `/src/lib`).
- Here, having both is an artifact of the rapid v0 generation where application pages sat in `/app` while data/config files sat in `/src`. In later sprint consolidation, all application source code can be cleanly organized.
